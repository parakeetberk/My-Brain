## Two field conventions the board parses

Added 2026-09-01 with the `cost` and `due` columns. **Both are parsed by convention, never guessed**, because a wrong date or price on a board row is worse than a blank one.

- **A due date is written `due YYYY-MM-DD`** anywhere in the row. Nothing else is read as a date.
- **A cost is written `cost $N` or `est. cost $N`.** A bare dollar figure in a sentence is **not** read as the row's price - *"nearby $100K+ communities"* is prose about money, and an early version of the parser priced a row at $100K because of it.

## Rules

- **The ID lives in the markdown**, as a leading code span on the row. It is not generated at render time, so it survives every rebuild of [[00-Meta/open-board]].
- **Never renumber, never recycle.** A closed item's ID retires with it. Gaps in the sequence are evidence of completed work.
- **A new row takes the next number** in its register, not the lowest free one.
- **Austin closes by ID.** *"PF-0324, Congress sold, close it"* is a complete instruction. Do not ask him to re-describe it.
- **Source links get resolved on demand and written back**, never faked. See rule 15 for the connector detail that matters: a Teams chat search returns a usable `webUrl` only on the Graph Search path, so run it **without** date filters when the goal is a link.
