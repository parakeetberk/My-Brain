# Decision: the five rulings governing the retired Claude Code vault merge

**Date:** 2026-09-03
**Status:** ruled, all five. Apply rather than re-open.
**Owner:** Austin Berk

## The question

A second, earlier Brain existed as a Claude Code vault at `C:\Users\AustinBerk\Documents\Claude\Code\brain\`. The 2026-08-31 fold moved most of it into this Brain but left five genuine conflicts, each of which needed a ruling before any remaining file could move. **Any session or agent working the migration applies these. It does not re-open them.**

## The five rulings

**1. Unit count. This Brain's figure wins.** `CLAUDE.md`'s 67 active communities and 6,379 core units is authoritative. The ledger and the portfolio page already agree with it and its components already add exactly. **Nothing to edit; the requirement was satisfied before the ruling was written.** Any warehouse figure that surfaces later carries its as-of and its method, is labelled `SINGLE-SOURCE`, and never stands as the unit count.

**The correction underneath this ruling matters more than the ruling.** The conflict as first stated was wrong. A figure attributed to a named page in the old vault was never in that vault at all: it was this session's own arithmetic from a 2026-08-30 chat, published in an artifact and never written to any file. **Attributing a live number to a page that does not carry it is exactly the failure hard rule 3 exists to prevent**, and it was committed while writing the rule that cites hard rule 3. **The real gap is an open internal reconciliation, not an old-versus-new conflict**, tracked on `KP-0010`, `KP-0025 C1` and `TD-0004`, with a workbook against it. Figures in `00-Meta/numbers-ledger.md`.

**2. The old constitution is superseded wholesale.** It carried a three-item ceiling that rule 12 of this Brain replaced on 2026-09-01, and the record of what that ceiling cost in a single day is on the delegation board. **It does not merge. It is archived as the artefact rules 10, 11 and 15 came out of**, and nothing in it overrides a rule here. Do not copy any of its rules forward without checking against `CLAUDE.md` first.

**3. Parked decisions map onto existing `PD` IDs.** The old vault held 19 rows with no IDs. **Map them onto the `PD` IDs they already correspond to; anything genuinely new takes the next number in sequence.** Never renumber and never recycle. **Produce the mapping as a table before writing anything**, because a row that cannot be matched is a candidate for a new ID rather than an automatic one, and some of the 19 are already closed.

**4. Nothing migrates before a dash pass.** This Brain's voice rule is absolute, no em dashes or en dashes ever, and every file in the old vault uses them heavily. **No file migrates as-is.** **Rewrite the sentence rather than swapping the character**: an em dash usually marks a clause that should be its own sentence or sit inside commas, and a find-and-replace to a hyphen produces prose that reads wrong, which is the thing the rule exists to prevent.

**5. Karen Doner is outside counsel, not a personnel matter.** Austin: *"Karen Doner is Parakeet and affiliates employment attorney."* Her page belongs in `10-Business/outside-help/` and rule 7 does not apply to the page itself, because she is a vendor relationship. **The nuance that does still bite: she is an employment attorney, so the matters she advises on will frequently be personnel matters.** The page about her is open. Specific employee matters stay in the private assessment files, never on her page.

## What the reconciliation found once the rulings were applied

**The 2026-08-31 fold was more complete than anyone assumed.** All ten files in the index and reference scope came back `SUPERSEDED`, every one of them already here and every one of them the old copy plus a provenance header. Twelve of the 26 entity, domain and decision files were already inside this Brain byte for byte apart from path rewrites. **So the migration question was never "what should move." It was "what got dropped on the way in,"** and the answer was three things.

**The old `open-loops.md` is not a source to migrate. It is the direct ancestor of the commitments register**, forked out of it on 2026-08-31. Both files kept running for four more days and diverged in both directions. **66 of its 69 rows already carry IDs here.** Three did not, plus one missing archive entry.
