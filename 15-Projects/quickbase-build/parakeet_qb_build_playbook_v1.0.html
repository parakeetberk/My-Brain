How to Use This Playbook

This playbook translates the three locked build specs (WF001 v1.2, WF002 v1.3, WF003 v1.1) into ordered, step-by-step QuickBase and FastField configuration instructions. It is a build guide, not a spec repeat — it tells you how to configure, not just what to configure.


How to work through it:

  • Phase 0 first — always. Pre-build setup must be complete before any table is created.
  • Phase 1 second — shared reference tables are dependencies for all three workflows. Build them once.
  • Phase 2, 3, 4 — build each workflow in order. WF003 can be built before WF002 if preferred (it is upstream), but WF001 is independent and can run in parallel.
  • Phase 5 last — cross-workflow wiring and end-to-end testing.

Key conventions:

  • Auto fields are system-generated — never manual entry.
  • Required fields must be set before the form can save.
  • Gate fields are enforced by hard-stop validation — no bypass allowed.
  • Relationship fields link to another table via QB relationship (never free-text for linked data).
  • All field names, automation IDs, and gate IDs match the approved specs exactly. Do not rename.
  • QB status fields (Workflow Stage, Lot Status, Asset Status, etc.) are set by automation only — Community Managers never manually set these fields.
