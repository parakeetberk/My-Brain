Section 01 Document Purpose WF002 — Rehab

This specification defines the complete Quickbase (QB) tables, workflow stages, automations, gate rules, and FastField form required to build Workflow #002: Rehab. This workflow manages the end-to-end process of taking a vacant home from initial identification of rehab need through completed rehab, final walkthrough approval, and handoff to the listing workflow.

Workflow #002 is independent of Workflow #001 (Home Ordering). It applies to existing homes in the portfolio — homes that have been vacated via move-out or otherwise identified as needing rehab before they can be re-listed or re-occupied. WF001 covers new homes ordered from manufacturers; WF002 covers existing portfolio assets.

System of Record: Rent Manager (RM) remains the system of record for asset data, financial records, and insurance. This build complements RM — it does not replace or auto-modify any RM records. All Rent Manager field references in QB are cross-references only.
BoundaryDetail
In ScopeAll 9 rehab workflow stages; QB Rehab Records, Rehab Tasks, and Walkthrough Records tables; FastField Rehab Walkthrough Punchlist form; FastField → QB webhook integration; all automations and gate rules defined in this document
Out of ScopeRent Manager asset record creation or modification; marketing execution post-listing; Workflow #001 (new home ordering); financial/invoice processing; vendor portal or external work order systems
Dependent WorkflowsWF001 Stage 9 (Listing) — WF002's final stage hands off to the listing process. Move Out workflow — completed move-out can auto-trigger a WF002 record.

Section 06 Cascading Dropdown Architecture (WF002) Community → Lot → Asset

All Community, Lot, and Asset selections in WF002 follow the master cascading chain defined in WF001 Section 3A. The cascade is: Community → Lot → Asset. Each selection filters the next dropdown to show only valid child records. WF002 applies the following filters specific to the rehab context.

WF002 Cascading Dropdown Filter Rules
DropdownFilter AppliedNotes
CommunityAll active communitiesNo filter — all communities shown. User selects the community where the home is located.
LotLot Status = In Rehab OR AvailableFilters to lots in the selected Community that are vacant and eligible for rehab tracking.
AssetAsset Status = In RehabFilters to the specific home on the selected lot that is actively in rehab.
Asset Status Value (Open Item O-WF002-07): "In Rehab" must be added as a valid Asset Status value in the Assets table. Confirm the full set of Asset Status values with Austin before building the Assets table. Recommended values: In Rehab / Available / Listed / Occupied / Demo / Other.
FastField Pre-Population: When a field crew member taps the FastField launch link in QB, Community, Lot, Asset, and Rehab Record ID are passed as URL parameters and pre-populated into the form header fields. These four fields are locked (read-only) on the form — the inspector cannot change them. This ensures every submission is correctly matched to its parent QB record.
Lot Status for Rehab (Open Item O-WF002-08): A vacated lot currently carries Lot Status = Available. Confirm whether a separate Lot Status value of "In Rehab" is needed, or whether rehab state is tracked at the Asset Status level only. The current spec tracks rehab state on the Asset (Asset Status = In Rehab) and leaves Lot Status = Available, preserving lot availability metrics while the asset is being rehabbed.
Section 07 Automations 11 Automations — QB Pipelines

All automations run in QB Pipelines and fire on record events (field changes, new record creation, or webhook receipt) unless marked Daily. Every automation is numbered with a persistent ID for traceability. Automations are not activated until all Open Items in Section 9 that affect the relevant logic are resolved.

Hard Rule: Automations A-RH-06 and A-RH-07 are mutually exclusive — exactly one fires per walkthrough submission. They are triggered by the value of Walkthrough Status. Both cannot fire on the same record event.
Automation Register — WF002
IDTriggerActionTiming

A-RH-04 Rehab Record Stage changed to Walkthrough Scheduled Generate pre-populated FastField launch link (Community + Lot + Asset + Rehab Record ID as URL parameters). Set Walkthrough Scheduled Date. Notify Community Manager by email with the FastField link. Immediate

Section 08 Gate Rules 8 Hard Stops — No Bypass Permitted
Enforcement Principle: Gate rules are hard stops implemented as QB field-level validation or Pipeline checks. A gate that can be bypassed is not a gate. The Rehab Stage field must be locked to its current value until all conditions for the target stage are satisfied. Soft warnings are non-compliant.
Gate Rules — WF002 Rehab
Gate IDStage TransitionCondition(s) — All Must Be True
G-RH-01 Rehab Identified → Scope Assessed Scope Notes field is not blank. Community, Lot, and Asset are all linked (not null). RM Asset Record # and RM Unit # populated (warn if blank, not hard-block — per Open Item O-WF002-01).
G-RH-02 Scope Assessed → Work Assigned Assigned To field is not blank.
G-RH-03 Work Assigned → Work In Progress At least one Rehab Task record exists linked to this Rehab Record. At least one Rehab Task has Status = In Progress or Complete.
G-RH-04 Work In Progress → Walkthrough Scheduled Walkthrough Scheduled Date is populated and is not a past date.
G-RH-05 Walkthrough Scheduled → Walkthrough Complete At least one Rehab Walkthrough Record exists linked to this Rehab Record (confirmed via FastField webhook receipt and A-RH-05 execution).
G-RH-06 Walkthrough Complete → Approved Walkthrough Status = "Approved as Ready to Market". Will not advance if Walkthrough Status = Needs Additional Items / Not Ready / Vendor Needs to Finish. Stage will route to Items To Resolve (Stage 7) via A-RH-07 instead.
G-RH-07 Items To Resolve → Walkthrough Scheduled All Rehab Tasks linked to this Rehab Record have Status = Complete. No tasks with Status = Not Started / In Progress / Blocked. Enforces that re-inspection is not booked until all open items are resolved.
G-RH-08 Approved → Handed to Listing Approved Date is populated. Asset Status = Available. Listing team confirmation received (method per Open Item O-WF002-05).
