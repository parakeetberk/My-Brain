01Overview

Purpose

This document defines the complete Quickbase and FastField build for the Home Ordering, Delivery & Set workflow. It is the single source of truth for the configuration. Use it to build, QA, and train staff on the system.

Scope

Covers all 11 steps of the SOP from Infill Need Identified through Home Listed for Sale. MRB tracking (Rent Manager) is noted as a parallel system — this build does not replicate Rent Manager; it complements it.

Out of Scope

  • MRB issue management (stays in Rent Manager)
  • Rent Manager asset records (stays in Rent Manager — referenced via cross-reference fields only)
  • Marketing execution after listing

Systems Involved

QuickbaseWorkflow engine, status tracking, task assignment, internal notifications, gate enforcement
FastFieldField-capture forms (delivery, punch list, listing) — mobile, works offline, syncs to QB
Rent ManagerSystem of record for asset data — referenced, not replaced

The build uses a relational, multi-table model. Each table has a specific job. They are linked so that one home order record drives all downstream tasks and forms. Every child table links back to Home Orders as its parent.

07Quickbase ↔ FastField Integration

Method: FastField supports webhook-based data push on form submission. Each FastField form submission sends a JSON payload to a Quickbase webhook endpoint, creating or updating the corresponding child record in Quickbase automatically.

Integration Map

FastField FormQB Table TargetAction on Submit
Form 1: Home Delivery ConfirmationDelivery RecordsCreates new Delivery Record linked to Home Order — triggers A7
Form 2: Interior Punch ListPunch List RecordsCreates new Punch List Record linked to Home Order — triggers A8
Form 3: Listing FormListing RecordsCreates new Listing Record linked to Home Order — triggers A11

Matching Logic

Each FastField form includes a Home Order # field. This value is the key used to look up and link the new child record in Quickbase. The Home Order # must be typed or scanned accurately by field staff — it is the only automated link between field data and the QB record. Train all field staff on this requirement before go-live.

Required Setup Steps

  1. Create webhook endpoint in Quickbase (via QB Pipelines or API endpoint configuration)
  2. Configure each FastField form to POST its payload to the QB endpoint on submit
  3. Map FastField field names to QB field names for each of the 3 forms (field-by-field mapping)
  4. Test each form with a dummy submission and verify child record created correctly in QB
  5. Confirm automations A7, A8, A11 fire correctly on test record creation
Short-Term Bridge Option (see Open Item O1): If webhook integration is complex to configure initially, FastField data can be exported to CSV and imported into Quickbase manually as a bridge. Build tables and field names to match FastField exactly so migration to webhook is clean when ready.

08Workflow Gate Rules (Hard Stops)

These rules prevent a record from advancing to the next stage without required data or confirmations. Gates are enforced via Quickbase form validation and QB Pipelines conditional logic. These are non-negotiable — bypassing them defeats the purpose of the system.

GateStage TransitionRequired Fields / Conditions
G1 Infill Need Identified → Lot Due Diligence Lot Number assigned to record; Infill Reason entered
G2 Lot Due Diligence → Home Selected Lots table: Site Survey Completed = Yes (or waiver documented in Notes); all due diligence fields filled on Lot record
G3 Home Selected → Order Placed Floor Plan Name and Production Line confirmed by Operations; Ops task marked Complete
G4 Order Placed → File & Asset Setup Purchase Price entered; Accounting setup task marked Complete
G5 In Production → Delivery Scheduled Serial Number field is not blank — must be entered before delivery can be scheduled
G6 Delivery Scheduled → Delivered Delivery Records child record exists — FastField Form 1 must have been submitted and synced
G7 Delivered → Home Set Lot Fit Issue = unchecked (no issue) OR new lot confirmed by Sales and Asset Mgmt and Lot Fit Issue cleared
G8 Home Set → Listed — Complete Listing Records child record exists AND all 6 pre-listing checklist items = Yes — both conditions required

09Build Sequence (Recommended)

Build in this order to avoid relationship rework. Parent tables must exist before child tables can reference them. Complete each step fully — including testing — before moving to the next.
  1. Build the Lots table — reference data first; no dependencies on other tables
  2. Build the Home Orders table — master record with all fields; add Lot relationship to Lots table
  3. Build the Workflow Tasks table — link to Home Orders as parent; confirm relationship displays correctly
  4. Build Delivery Records table — link to Home Orders; all fields per Section 3.5
  5. Build Punch List Records table — link to Home Orders; all fields per Section 3.6
  6. Build Listing Records table — link to Home Orders; all fields per Section 3.7
  7. Create all Quickbase forms — Forms F1–F10; link each to appropriate table
  8. Create all views and dashboards — Views V1–V6 per Section 4.2
  9. Configure automations — A1 through A11 in order; test each before proceeding
  10. Set up gate rules — form validation and QB Pipelines conditional logic per Section 8
  11. Build FastField Form 1 (Delivery Confirmation) — configure fields, set up integration, test end-to-end
  12. Build FastField Form 2 (Punch List) — configure 100-point checklist (pending O2), test end-to-end
  13. Build FastField Form 3 (Listing Form) — configure hard validation, test end-to-end
  14. End-to-end test — walk one dummy home order through all 11 stages; confirm all gates and automations fire correctly; verify all FastField syncs create correct QB child records
  15. Team training — role-specific walkthroughs for Sales, Construction, Operations, Accounting, and Asset Mgmt; confirm mobile FastField access for field staff
