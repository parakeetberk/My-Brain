Section 01 Document Purpose & Scope WF003 — Asset Disposition Review — v1.0 — 08/19/26

This document specifies the Quickbase build for WF003 — Asset Disposition Review. WF003 formalizes the weekly Monday morning Asset Management meeting in Quickbase — capturing disposition decisions per vacated unit and automatically triggering the appropriate downstream workflow based on that decision.

Design Intent: Today the Monday meeting runs entirely outside Quickbase. Dispositions (Rehab / Demo / Turn for Sale) are decided verbally and entered manually into downstream systems — or not entered at all. WF003 creates a structured record of every meeting, every unit reviewed, and every decision made. This gives the company a full disposition audit trail and removes manual handoffs as the trigger for WF002 and future Demo/Listing workflows.

Section 03 Disposition Outcomes Five possible outcomes — each drives a different QB action

All five dispositions are available on every Disposition Item. The assigned value determines what automation fires and what downstream workflow (if any) is triggered.

Rehab — Unit requires rehabilitation before re-listing
  • Automation A-DR-01 fires immediately on save.
  • Creates a new WF002 Rehab Record — Community, Lot, and Asset passed automatically.
  • Sets Lot Status → Lot-In Rehab on the linked Lot record.
  • Sets Asset Status → Rehab in Process on the linked Asset record.
  • Downstream Record ID field on the Disposition Item is auto-populated with the new Rehab Record ID (e.g., RH-2026-004).
  • Item Status auto-advances to Actioned.
Demo — Unit flagged for demolition
  • Automation A-DR-02 fires immediately on save.
  • Sets Lot Status → Lot-Demo on the linked Lot record.
  • Sets Asset Status → To Be Demoed on the linked Asset record.
  • Sends notification to Ops team: unit flagged for Demo, meeting date, community, lot, and asset details included.
  • Item Status auto-advances to Actioned.
  • Note: Full Demo execution workflow (WF-Demo) is a future workflow. WF003 handles the flag and status update only.
Turn for Sale — Unit to be listed for sale
  • Automation A-DR-03 fires immediately on save.
  • Sets Asset Status → For Sale on the linked Asset record.
  • Sends notification to Listing team: unit approved for sale, meeting date, community, lot, asset, and any disposition notes included.
  • Item Status auto-advances to Actioned.
  • Note: Full Listing workflow (WF006) is a separate workflow. WF003 triggers the initial notification and status update only.
Hold — Decision deferred; unit held pending further information
  • Automation A-DR-05 fires: Item Status advances to Closed. No status changes to Lot or Asset.
  • Disposition Notes field should capture reason for hold and expected review date.
  • Unit should be re-added to the next meeting agenda (manual — recorder adds a new Disposition Item).
No Action — Reviewed; no disposition assigned at this time
  • Automation A-DR-05 fires: Item Status advances to Closed. No status changes to Lot or Asset.
  • Record preserved for audit trail — unit was reviewed but no action was warranted.
Section 04 Item Stages (per Disposition Item)

Each Disposition Item moves through 4 stages. Meeting-level status is a separate field on the Disposition Meeting record and tracks aggregate progress.

#StageOwnerDescription
1 Pending Review Recorder Disposition Item created in QB. Community, Lot, and Asset linked. Current Lot Status and Asset Status captured as a snapshot. No disposition assigned yet. Gate: Community, Lot, and Asset must all be set before Item Status can advance.
2 Reviewed Asset Mgmt Meeting attendees review the unit. Disposition assigned (Rehab / Demo / Turn for Sale / Hold / No Action). Disposition Notes entered if applicable. Gate: Disposition field must be set (not blank) before advancing from Pending Review. Reviewed Date auto-stamped.
3 Actioned Auto (QB) Set automatically by automation upon Disposition assignment for Rehab, Demo, and Turn for Sale. Downstream record created or notification sent. Actioned Date auto-stamped. Downstream Record ID populated where applicable.
4 Closed Auto / Ops Set automatically for Hold and No Action (no downstream workflow triggered). For Rehab / Demo / Turn for Sale: auto-closes when downstream record confirmed. Meeting Status on parent record auto-sets to Closed when all items reach Actioned or Closed.

Cascade Logic (Community → Lot → Asset): All three relationship fields use the same dynamic cascade architecture established in WF001 and WF002 (D-011). Community is selected first; Lot dropdown filters to that community only; Asset dropdown filters to that lot only. Context filter for WF003: no status restriction on Lot or Asset — any recently vacated unit may be under review regardless of current status. The meeting recorder selects the unit and the status snapshot fields capture the current state automatically.
Section 06 Automations 5 automations — A-DR-01 through A-DR-05

All automations trigger immediately on save (not on a schedule). Timing column below confirms trigger type.

IDTriggerTimingAction
A-DR-01 Disposition Item saved with Disposition = Rehab Immediate Create WF002 Rehab Record — passes Community, Lot, Asset, Meeting Date (from parent DM record), and Disposition Notes to the new Rehab Record. New Rehab Record ID auto-generated (RH-YYYY-###).
Update Lot record: Lot Status → Lot-In Rehab.
Update Asset record: Asset Status → Rehab in Process.
Update Disposition Item: Downstream Record ID = new RH-####; Item Status → Actioned; Actioned Date → today.
A-DR-02 Disposition Item saved with Disposition = Demo Immediate Update Lot record: Lot Status → Lot-Demo.
Update Asset record: Asset Status → To Be Demoed.
Send notification to Ops team: "[Asset ID] at [Community] has been flagged for Demo at the [Meeting Date] Asset Disposition meeting. Lot: [Lot]. Notes: [Disposition Notes]."
Update Disposition Item: Item Status → Actioned; Actioned Date → today.
A-DR-03 Disposition Item saved with Disposition = Turn for Sale Immediate Update Asset record: Asset Status → For Sale.
Send notification to Listing team: "[Asset ID] at [Community] has been approved for sale at the [Meeting Date] Asset Disposition meeting. Lot: [Lot]. Notes: [Disposition Notes]. Please initiate the listing process."
Update Disposition Item: Item Status → Actioned; Actioned Date → today.
A-DR-04 All Disposition Items for a Disposition Meeting = Actioned or Closed Immediate Update Disposition Meeting record: Meeting Status → Closed.
A-DR-05 Disposition Item saved with Disposition = Hold or No Action Immediate Update Disposition Item: Item Status → Closed. No status changes to Lot or Asset record. Record preserved for audit trail.
A-DR-01 Integration with WF002: The Rehab Record created by A-DR-01 is a fully formed WF002 record at Stage 1 (Rehab Identified). The meeting recorder does not need to open WF002 separately — the record is created automatically and the Rehab team is notified per WF002 automation A-RH-02 (existing). The WF003 Disposition Item and the WF002 Rehab Record are linked via the Downstream Record ID field for full traceability.
Section 07 Gate Rules 3 hard stops — no exceptions

Gate rules are enforced at the QB form level and automation level. They are hard stops — the record cannot be saved in a state that violates a gate rule.

Gate IDRule
G-DR-01 Disposition required before Reviewed status. Item Status cannot be set to Reviewed (or beyond) unless Disposition is set to a non-blank value (Rehab / Demo / Turn for Sale / Hold / No Action). A unit cannot be marked as reviewed without a disposition decision on record.
G-DR-02 All items must be Actioned or Closed before Meeting can close. Disposition Meeting Status cannot be manually set to Closed if any linked Disposition Item = Pending Review or Reviewed. Meeting closure is auto-handled by A-DR-04 — manual close override is blocked. This ensures no unit is forgotten at an open meeting.
G-DR-03 No duplicate active Disposition Items for the same Lot in the same meeting. A Disposition Item cannot be created for a Lot that already has a non-Closed Disposition Item linked to the same Disposition Meeting. If a unit needs to be re-reviewed, the existing item must be closed first or a new meeting must be created.
Section 08 Relationships & Downstream Workflows
WorkflowRelationship to WF003
WF002 — Rehab Primary downstream. When Disposition = Rehab, A-DR-01 auto-creates a WF002 Rehab Record. Community, Lot, Asset, and Disposition Notes passed automatically. The WF003 Disposition Item links to the created Rehab Record via Downstream Record ID. WF003 provides the official trigger and audit trail for every WF002 Rehab Record created via meeting disposition.
Demo Workflow (future) Not yet specced. When Disposition = Demo, WF003 sets Lot Status → Lot-Demo and Asset Status → To Be Demoed and notifies Ops. The full Demo execution workflow will be specced separately. WF003 creates the disposition record and status changes; the Demo WF will handle execution tracking.
WF006 — Listings (future) Not yet specced. When Disposition = Turn for Sale, WF003 sets Asset Status → For Sale and notifies Listing team. The full Listing workflow will be specced separately. WF003 creates the disposition record and initial status; WF006 handles the listing execution.
Move Out Workflow (future) A completed Move Out record may pre-populate the Lot and Asset fields on a new Disposition Item — the unit appears on the next meeting's agenda automatically. Move Out WF is not yet specced; this integration point is noted for future design.
Communities Table WF003 Disposition Items use the same Communities reference table as WF001 and WF002. No new community data required.
Lot Status Table (LS) WF003 automations write to Lot Status on the linked Lot record using the same LS reference table defined in WF002. No additional Lot Status values required for WF003.
Asset Status Table (AS) WF003 automations write to Asset Status on the linked Asset record using the same AS reference table defined in WF002. Values used: Rehab in Process (Rehab), To Be Demoed (Demo), For Sale (Turn for Sale).
Section 09 Reports & Views

Standard QB reports to build alongside WF003. All reports are QB-native — no external BI tool required at this stage.

Report NameDescription
This Week's Meeting Shows the current week's Disposition Meeting and all linked Disposition Items. Default view for the Monday meeting recorder. Columns: Item ID, Community, Lot, Asset, Status at Review, Disposition, Disposition Notes, Item Status, Downstream Record ID.
All Open Meetings Lists all Disposition Meetings where Meeting Status = Open. Used to confirm no meeting has outstanding unactioned items. Columns: Meeting ID, Meeting Date, Facilitator, Total Units Reviewed, Rehab Count, Demo Count, Turn for Sale Count, Hold Count.
Disposition History by Community All Disposition Items grouped by Community. Filterable by date range and disposition type. Used for portfolio-level reporting and asset management reviews.
Rehab Pipeline Source All Disposition Items where Disposition = Rehab. Links through to associated WF002 Rehab Records. Shows disposition date, community, lot, asset, and current WF002 stage.
Pending Items (Unactioned) All Disposition Items where Item Status = Pending Review or Reviewed. Used to identify any items that have stalled without an outcome. Expected to be empty at end of each meeting week.
