Section 01 Overview

Purpose

This document defines the complete Quickbase and FastField build for the Home Ordering, Delivery & Set workflow. It is the single source of truth for the configuration. Use it to build, QA, and train staff on the system.

Version 1.2 incorporates the actual 89-item Construction Installation Checklist and 71-item Ops & Sales Readiness Checklist submitted by the field teams, expands the workflow to 12 stages, and establishes the system-wide Cascading Dropdown Architecture (Section 3A) as the standard for all Community → Lot → Asset selections across every Quickbase and FastField form.

Scope

Covers all 12 stages from Infill Need Identified through Listed — Complete. Rent Manager (RM) remains the system of record for asset records and financial data — this build complements RM, it does not replace it.

BoundaryDetail
In scopeAll 12 workflow stages; QB tables, forms, automations, gates; FastField forms; FF↔QB integration
Out of scopeRent Manager asset record creation; marketing execution after listing; other workflows (Rehab, Resident Mgmt)

Section 3A  NEW IN v1.2 Cascading Dropdown Architecture System-Wide Standard
SYSTEM-WIDE STANDARD — NO EXCEPTIONS. Every form in Quickbase and FastField that includes Community, Lot, or Asset selection MUST follow these rules. This applies to all 15+ forms system-wide, not just Workflow #001.

The Hierarchy

Community
    └── Lot              (filtered by Community)
            └── Asset    (filtered by Lot + Asset Status)

Each tier is a relationship field (never free-text). Selecting a value at one tier immediately narrows the options at the next tier. Community is always unfiltered. Lot is always filtered to the selected Community, then further filtered by Lot Status based on form context. Asset is always filtered to the selected Lot, then further filtered by Asset Status based on form context.

This table is the authoritative reference. When building any form, find the form in this table and apply the filter exactly as specified.

Move In / Move Out — Full Cascade Logic

This is the most complex filter scenario. The Lot list re-filters dynamically based on the Move In vs. Move Out selection. Get this wrong and incorrect lots are presented to users.

Step 1: User selects Community → all lots in that Community load.

Step 2: User selects Move In or Move Out → Lot list immediately re-filters:

SelectionLot Filter AppliedAsset Filter
Move In Lot Status = Available (vacant lots only) If "Community Owned Home Sale?" = YES → show listed assets on Lot. If NO → no asset field shown
Move Out Lot Status = Occupied (occupied lots only) Assets on selected Lot (the home being vacated)

Why this matters: Without this filter, a Move In form could accidentally select an already-occupied lot. Without it on Move Out, it could target a vacant lot that has no one to move out. The filter eliminates those errors at the data entry point — not after the fact in a report.

QB Form Configuration — Step by Step

  1. On every QB form, set the Lot field as a relationship lookup field (not free-text)
  2. In the Lot field settings, enable "Filter related records" → filter where Community field on Lot record matches the Community field on the current form
  3. For status-based filters: add a second filter condition — Lot Status = [target value from the reference table above]
  4. For Asset field: same pattern — filter where Lot field matches, plus Asset Status = [target value]
  5. Test every form: select a Community, verify only correct Lots appear; select a Lot, verify only correct Assets appear

7. Integration Architecture

Parakeet Communities operates a three-system stack. Rent Manager is the authoritative system of record for all asset identifiers, resident accounts, lease data, and financial ledgers. Quickbase is the operational workflow layer — it orchestrates checklist progression, status tracking, and role-based approvals. FastField is the mobile field-capture layer for construction and operations inspections. No system replaces another; data flows in one direction per boundary and is never dual-entered.

7.1 Rent Manager → Quickbase (Master Reference Sync)

Rent Manager is not replaced by Quickbase. It remains the canonical source for community names, lot identifiers, unit addresses, and lease records. Quickbase references Rent Manager IDs — it does not replicate financials or lease contracts.

7.2 FastField → Quickbase (Inspection Results Push)

FastField dispatches completed inspection submissions to Quickbase via webhook or REST API call. Each submission maps to a single Quickbase record by Lot ID. The push is one-directional: FastField → QB only. No data flows from QB back into FastField forms after dispatch.

8. Gate Rules

Gate rules define the precise conditions that must be satisfied before a lot or home order advances to the next workflow stage. Gates are enforced by Quickbase field-level validation and automation logic — no manual override is possible without a documented exception. All gate conditions are AND conditions unless explicitly marked OR.

Enforcement Principle: A gate that can be bypassed is not a gate. Every gate below must be implemented as a hard block in Quickbase — the relevant status field must be locked to the current value until all conditions are satisfied. Soft warnings that allow continuation are not compliant.
