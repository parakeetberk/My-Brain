Version History Section 01 Document Purpose & Scope WF003 — Asset Disposition Review — v1.1 — 08/19/26 This document specifies the Quickbase build for WF003 — Asset Disposition Review . WF003 formalizes the weekly Monday morning Asset Management meeting in Quickbase — capturing disposition decisions per vacated unit and automatically triggering the appropriate downstream workflow based on that decision. Design Intent: Today the Monday meeting runs entirely outside Quickbase. Dispositions (Rehab / Demo / Turn for Sale) are decided verbally and entered manually into downstream systems — or not entered at all. WF003 creates a structured record of every meeting, every unit reviewed, and every decision made. This gives the company a full disposition audit trail and removes manual handoffs as the trigger for WF002 and future Demo/Listing workflows. Item Detail Workflow Name Asset Disposition Review Workflow ID WF003 Primary Purpose Record Monday Asset Disposition meeting outcomes in QB per unit; auto-trigger downstream workflows based on disposition assigned. Meeting Cadence Weekly — every Monday AM Meeting Facilitator Asset Management team Participants Asset Management, Ops, Construction, Sales Disposition Options Rehab / Demo / Turn for Sale / Hold / No Action Downstream Workflows WF002 Rehab (Disposition = Rehab) · Demo workflow (Disposition = Demo — future WF) · Listings (Disposition = Turn for Sale — future WF) FastField Forms None — QB-only workflow (office / meeting data entry) QB Tables 2 — Disposition Meetings (DM) + Disposition Items (DI) In Scope Weekly Monday meeting record creation; per-unit Disposition Item records; disposition assignment (all 5 values); automations triggering WF002 on Rehab disposition; lot and asset status updates on Demo and Turn for Sale; meeting-level rollups and reporting; audit trail of all disposition decisions Out of Scope Demo execution workflow (future WF); listing execution workflow (future WF); Rent Manager record creation or modification; financial tracking (handled in WF002); FastField field forms; units not yet reviewed / not yet vacated Dependent Workflows WF002 Rehab — triggered automatically when Disposition = Rehab. Future Demo WF — triggered when Disposition = Demo. Future Listing WF — triggered when Disposition = Turn for Sale. Section 02 Workflow Overview WF003 operates at two levels: a Meeting record (one per Monday meeting) and Item records (one per unit reviewed at that meeting). The meeting recorder creates items in QB before or during the meeting. After each disposition is assigned, QB automations fire immediately — no manual handoff required. 1 Meeting Created Asset Mgmt › 2 Items Added Recorder › 3 Pending Review Meeting › 4 Reviewed Asset Mgmt › 5 Actioned Auto › 6 Closed Auto / Ops Stages 3–6 apply per Disposition Item. Meeting record status = Open until all items are Actioned or Closed, then auto-sets to Closed. QB Tables 2 Item Stages 4 Automations 5 Gate Rules 3 FastField Forms None Disposition Values 5 Section 03 Disposition Outcomes Five possible outcomes — each drives a different QB action All five dispositions are available on every Disposition Item. The assigned value determines what automation fires and what downstream workflow (if any) is triggered. Rehab — Unit requires rehabilitation before re-listing Automation A-DR-01 fires immediately on save. Creates a new WF002 Rehab Record — Community, Lot, and Asset passed automatically. Sets Lot Status → Lot-In Rehab on the linked Lot record. Sets Asset Status → Rehab in Process on the linked Asset record. Downstream Record ID field on the Disposition Item is auto-populated with the new Rehab Record ID (e.g., RH-2026-004). Item Status auto-advances to Actioned . Demo — Unit flagged for demolition Automation A-DR-02 fires immediately on save. Sets Lot Status → Lot-Demo on the linked Lot record. Sets Asset Status → To Be Demoed on the linked Asset record. Sends notification to Ops team: unit flagged for Demo, meeting date, community, lot, and asset details included. Item Status auto-advances to Actioned . Note: Full Demo execution workflow (WF-Demo) is a future workflow. WF003 handles the flag and status update only. Turn for Sale — Unit to be listed for sale Automation A-DR-03 fires immediately on save. Sets Asset Status → For Sale on the linked Asset record. Sends notification to Listing team: unit approved for sale, meeting date, community, lot, asset, and any disposition notes included. Item Status auto-advances to Actioned . Note: Full Listing workflow (WF006) is a separate workflow. WF003 triggers the initial notification and status update only. Hold — Decision deferred; unit held pending further information Automation A-DR-05 fires: Item Status advances to Closed . No status changes to Lot or Asset. Disposition Notes field should capture reason for hold and expected review date. Unit should be re-added to the next meeting agenda (manual — recorder adds a new Disposition Item). No Action — Reviewed; no disposition assigned at this time Automation A-DR-05 fires: Item Status advances to Closed . No status changes to Lot or Asset. Record preserved for audit trail — unit was reviewed but no action was warranted. Section 04 Item Stages (per Disposition Item) Each Disposition Item moves through 4 stages. Meeting-level status is a separate field on the Disposition Meeting record and tracks aggregate progress. # Stage Owner Description 1 Pending Review Recorder Disposition Item created in QB. Community, Lot, and Asset linked. Current Lot Status and Asset Status captured as a snapshot. No disposition assigned yet. Gate: Community, Lot, and Asset must all be set before Item Status can advance. 2 Reviewed Asset Mgmt Meeting attendees review the unit. Disposition assigned (Rehab / Demo / Turn for Sale / Hold / No Action). Disposition Notes entered if applicable. Gate: Disposition field must be set (not blank) before advancing from Pending Review. Reviewed Date auto-stamped. 3 Actioned Auto (QB) Set automatically by automation upon Disposition assignment for Rehab, Demo, and Turn for Sale. Downstream record created or notification sent. Actioned Date auto-stamped. Downstream Record ID populated where applicable. 4 Closed Auto / Ops Set automatically for Hold and No Action (no downstream workflow triggered). For Rehab / Demo / Turn for Sale: auto-closes when downstream record confirmed. Meeting Status on parent record auto-sets to Closed when all items reach Actioned or Closed. Section 05 Quickbase Tables 5A — Disposition Meetings (DM) One record per Monday meeting. Parent table. Record ID format: DM-YYYY-### Field Type Notes Meeting ID Text (auto) DM-YYYY-### format. Auto-generated on record creation. Meeting Date Date Required. Date of the Monday meeting. Format: mm/dd/yy. Soft warning fires if date selected is not a Monday — allows recorder to proceed (covers holiday week exceptions). Warning text: "This date is not a Monday. Asset Disposition meetings are typically held on Mondays. Confirm to proceed." Meeting Status Dropdown Values: Open / Closed. Defaults to Open on creation. Auto-set to Closed by A-DR-04 when all linked Disposition Items = Actioned or Closed. Facilitator User Required. QB user running the meeting — typically Asset Management lead. Participants Text (multi-line) Optional. Names or roles of attendees beyond the facilitator (Ops, Construction, Sales reps). Meeting Notes Text (multi-line) Optional. General meeting notes — not unit-specific (unit notes go on individual Disposition Items). Total Units Reviewed Count (rollup) Count of all linked Disposition Items. Auto-calculated. Rehab Count Count (rollup) Count of linked Disposition Items where Disposition = Rehab. Auto-calculated. Demo Count Count (rollup) Count of linked Disposition Items where Disposition = Demo. Auto-calculated. Turn for Sale Count Count (rollup) Count of linked Disposition Items where Disposition = Turn for Sale. Auto-calculated. Hold Count Count (rollup) Count of linked Disposition Items where Disposition = Hold. Auto-calculated. Created By User (auto) QB user who created the meeting record. Auto-stamped. Created Date Date/Time (auto) Auto-stamped on record creation. 5B — Disposition Items (DI) One record per unit reviewed at a meeting. Child of Disposition Meetings. Record ID format: DI-YYYY-### Field Type Notes Item ID Text (auto) DI-YYYY-### format. Auto-generated on record creation. Meeting Relationship → Disposition Meetings Required. Links this item to the parent Monday meeting record (DM-YYYY-###). Community Relationship → Communities Required. Top of cascade. Filtered to active communities. Lot Relationship → Lots Required. Filtered dynamically to lots belonging to the selected Community. Asset Relationship → Assets Required. Filtered dynamically to assets on the selected Lot. Lot Status at Review Text (formula) Snapshot of the Lot's current Lot Status at time of review — pulled from the linked Lot record. Read-only. Preserved even if Lot Status changes after meeting. Asset Status at Review Text (formula) Snapshot of the Asset's current Asset Status at time of review — pulled from the linked Asset record. Read-only. Preserved even if Asset Status changes after meeting. Disposition Dropdown Values: (blank — Pending) / Rehab / Demo / Turn for Sale / Hold / No Action. Defaults to blank. Setting this field to a non-blank value triggers the appropriate automation. Required before advancing Item Status. Disposition Notes Text (multi-line) Optional. Reason for disposition, specific scope notes, or hold details. Required when Disposition = Hold (open item — O-WF003-001). Assigned To User Optional. QB user responsible for following up on this item (e.g., the Ops rep who will initiate WF002). Item Status Dropdown Values: Pending Review / Reviewed / Actioned / Closed. Defaults to Pending Review on creation. Drives automations and gate rules. Downstream Record ID Text (auto) Auto-populated by automation with the ID of the downstream record created — e.g., RH-2026-004 for a Rehab disposition. Empty for Hold and No Action. Reviewed Date Date (auto) Auto-stamped when Item Status advances to Reviewed. Actioned Date Date (auto) Auto-stamped when Item Status advances to Actioned. Created By User (auto) QB user who created this Disposition Item. Auto-stamped. Created Date Date/Time (auto) Auto-stamped on record creation. Cascade Logic (Community → Lot → Asset): All three relationship fields use the same dynamic cascade architecture established in WF001 and WF002 (D-011). Community is selected first; Lot dropdown filters to that community only; Asset dropdown filters to that lot only. Context filter for WF003: no status restriction on Lot or Asset — any recently vacated unit may be under review regardless of current status. The meeting recorder selects the unit and the status snapshot fields capture the current state automatically. Section 07 Gate Rules 3 hard stops — no exceptions Gate rules are enforced at the QB form level and automation level. They are hard stops — the record cannot be saved in a state that violates a gate rule. Gate ID Rule G-DR-01 Disposition required before Reviewed status. Item Status cannot be set to Reviewed (or beyond) unless Disposition is set to a non-blank value (Rehab / Demo / Turn for Sale / Hold / No Action). A unit cannot be marked as reviewed without a disposition decision on record. Additional rule: When Disposition = Hold, the Disposition Notes field is required — the record cannot be saved in Hold status without a written reason and expected re-review date. Error message: "Disposition Notes are required when Disposition = Hold. Please enter the reason for the hold and the expected re-review date." G-DR-02 All items must be Actioned or Closed before Meeting can close. Disposition Meeting Status cannot be manually set to Closed if any linked Disposition Item = Pending Review or Reviewed. Meeting closure is auto-handled by A-DR-04 — manual close override is blocked. This ensures no unit is forgotten at an open meeting. G-DR-03 Block with warning when unit already has an active WF002 Rehab Record. If a recorder attempts to create a Disposition Item for a Lot/Asset that already has an active (non-Closed) WF002 Rehab Record, QB blocks the save and displays: "This unit already has an active Rehab record in progress ([RH-ID]). A new Disposition Item cannot be created until the existing Rehab record is closed. Contact Ops if an exception is required." Future build: replace hard block with an exception approval workflow — recorder requests override, Ops Director approves. Separate rule: no duplicate non-Closed Disposition Items for the same Lot within the same meeting — recorder must close or remove the existing item first. Section 08 Relationships & Downstream Workflows Workflow Relationship to WF003 WF002 — Rehab Primary downstream. When Disposition = Rehab, A-DR-01 auto-creates a WF002 Rehab Record. Community, Lot, Asset, and Disposition Notes passed automatically. The WF003 Disposition Item links to the created Rehab Record via Downstream Record ID. WF003 provides the official trigger and audit trail for every WF002 Rehab Record created via meeting disposition. Demo Workflow (future) Not yet specced. When Disposition = Demo, WF003 sets Lot Status → Lot-Demo and Asset Status → To Be Demoed and notifies Ops. The full Demo execution workflow will be specced separately. WF003 creates the disposition record and status changes; the Demo WF will handle execution tracking. WF006 — Listings (future) Not yet specced. When Disposition = Turn for Sale, WF003 sets Asset Status → For Sale and notifies Listing team. The full Listing workflow will be specced separately. WF003 creates the disposition record and initial status; WF006 handles the listing execution. Move Out Workflow (future) A completed Move Out record may pre-populate the Lot and Asset fields on a new Disposition Item — the unit appears on the next meeting's agenda automatically. Move Out WF is not yet specced; this integration point is noted for future design. Communities Table WF003 Disposition Items use the same Communities reference table as WF001 and WF002. No new community data required. Lot Status Table (LS) WF003 automations write to Lot Status on the linked Lot record using the same LS reference table defined in WF002. No additional Lot Status values required for WF003. Asset Status Table (AS) WF003 automations write to Asset Status on the linked Asset record using the same AS reference table defined in WF002. Values used: Rehab in Process (Rehab), To Be Demoed (Demo), For Sale (Turn for Sale). Section 09 Reports & Views Standard QB reports to build alongside WF003.
